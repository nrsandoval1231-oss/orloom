## Recommendation / corrections to earlier local-only audit

Aura's current upstream is materially newer than the old local checkout and does include a PostgreSQL-backed, lease-fenced queue, worker isolation, and quota/provider-proxy concurrency controls. Those can inform Orloom's durable job and side-effect boundary. They remain Codex/OpenAI Responses-oriented and do not satisfy DeepSeek pool requirements. Forge has the strongest reusable *concepts* for deterministic governor, stuck diagnosis, and bounded lesson lifecycle, but Forge's package explicitly says Proprietary and Aura has no license file; the owner has explicitly authorized selective reuse in this directive; preserve attribution and do not infer public redistribution rights. Orloom should define its own stable contracts, adapt patterns only after reviewing trust boundaries, and preserve distinctions between unit-test evidence, live provider calls, deployed cloud runtime, and production readiness.
