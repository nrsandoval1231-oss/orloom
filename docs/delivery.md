# Certified delivery boundary

`POST /api/delivery` accepts the exact `orloom.delivery-command.v1` envelope: `version`, `missionId`, `sliceId`, `leaseEpoch`, `integratedSha`, `treeSha`, `reviewArtifactId`, `reviewArtifactDigest`, and `idempotencyKey`. It requires the existing owner session. Any extra field is rejected; repository, GitHub App/installation, branch, base, check set, permissions, and policy come only from controller-injected immutable configuration.

The server does not create GitHub credentials or discover R2 configuration from requests. Without an injected delivery controller the route returns 503. Startup remains closed by default. An operator can explicitly enable cloud/SQL integration and delivery with `ORLOOM_INTEGRATION_ENABLED=true` and `ORLOOM_DELIVERY_ENABLED=true`, bind one canonical repository to a private bare object store and private retained-review directory, and provide a strict private JSON policy through `ORLOOM_DELIVERY_POLICY_FILE`. The policy is accepted only when its repository matches the fixed integrator and its version, digest, image digest, and sole `node-repo-suite-v1` check match the configured trusted verifier. GitHub App private key and R2 keys support the existing `_FILE` convention and are never stored in `Config`.

The startup factory injects the same fixed local integration authority and review reader into the existing Governor/server dependencies. It makes no Git ref write, GitHub/R2 request, or provider call during startup. Explicitly enabled incomplete or mismatched configuration aborts startup with generic field-only errors; missing enable flags leave routes/capabilities closed. When configured, the existing Governor pipeline still requires the approved integrated slice, retained final certificate and review, exact local integration ref/tree, and controller services before publishing. It consumes an already uploaded reserved Orloom branch after exact remote SHA/tree readback; it does not push Git data.

The private delivery policy JSON has exactly these fields: `repository`, `appId`, `installationId`, `baseRef`, `baseSha`, `protectedRefs`, `checkIds`, `policyVersion`, `policyDigest`, `imageDigest`, and `checkName`. `checkIds` must be exactly `["node-repo-suite-v1"]`; the policy version, digest and image digest must match that check's configured immutable verifier policy. The policy repository must equal `ORLOOM_INTEGRATION_REPOSITORY`, and its App ID must equal `ORLOOM_GITHUB_APP_ID`. The pinned base ref must also be in `protectedRefs`. Policy and review files must be regular, non-symlink files; on POSIX they must be owned by the control-plane user and have no group/world permissions. Review files are named `<artifact-id>.json` under the fixed review directory; IDs are restricted to letters, digits, dot, underscore and hyphen, and reads are capped at 256 KiB.

Delivery publishes retained evidence as a completed Check and creates a draft pull request. It performs separate Check and PR GET readbacks and requires each returned ID to match the requested or created ID; the PR must remain open, draft, and unmerged with exact head/base identity. Durable effect claims prevent blind create retries after interruption. Missing or ambiguous outcomes remain unresolved for reconciliation. No automatic merge or deployment occurs, and GitHub does not execute CI.

Responses are 401 for a missing owner session, 400 for malformed or extra command fields, 409 when delivery prerequisites or exact evidence fences fail, and 503 when controller delivery authority is absent or delivery is unavailable. These controlled tests are not credentialed GitHub App/R2 or remote delivery proof. No startup Jev adapter is composed: a durable pre-dispatch reservation/reconciliation budget and distinct spend authorization are required before that separate capability can be enabled. Live provider use, actual App/R2 credentials, remote branch upload, CI execution, deployment, and publication remain unproven by this source composition.
