# Living Loom — Canonical Visual and Interaction Specification
Status: V3/V4 visual direction accepted; V5 live integration proposed.

## Non-negotiable visual baseline
- Preserve V3 cinematic woven torus and V4 inspectability. The full-screen view is a signature product experience, not the default practical workspace.
- Black/dark deep field; thousands of hair-fine ivory/gold/steel/blue threads; dimensional ring with depth, gentle luminous highlights, and restrained bloom.
- Central **mission/north star** remains visually fixed; orbiting/surrounding agent nodes feed the ring.
- Five codebase sectors: UI, Services, Data/Memory, Infrastructure, Verification. Texture, density, and activity vary by sector, but color alone is not the source of meaning.
- The ring may start as an idea point and gradually form. Construction/provisional strands are distinct from independently verified/settled strands.
- Completion is requirement-coverage based. Mission scope must be versioned. A newly approved scope can reopen the ring.
- Visible drift is backed by actual evidence/constraint conflicts; conflicting verification claims are withdrawn or flagged rather than cosmetically colored.

## Interaction
Rotate, zoom, pinch, focus a sector, select a code bundle, highlight dependencies, inspect source with file/line/fingerprint, inspect requirement links and evidence, replay history, filter agent activity, and return to full weave. Offer reduced-motion and performance modes. Mobile is first-class.

## Meaningful visual mappings
- Angular region: engineering sector.
- Sector extent: approved requirement scope, not arbitrary file count.
- Density: measured structural complexity/dependency intensity, **not health or progress**.
- Settled fibers: requirements with verified acceptance.
- Provisional fibers: planned/changed/unverified implementation.
- Displaced fibers: explicit, provenance-backed architectural conflict or unresolved traceability.
- Motion/flow: timestamped agent/build/test/review events.
- Trails/scars: history of repair/failure accessible via replay.
- Athena signals: decisions, hypotheses, learning evidence; no claim of autonomous wisdom absent validated outcomes.

## Agent activity around center
Architect maps purpose; builders feed code structures; validator sends verification pulse; reviewer produces independent findings; Athena sends reflection/strategy signal. A node's activity must derive from real run events in live mode. Never invent an agent, event, test, or percentage.

## V3/V4 prototype heritage
V1: Canvas projected torus. V2: synthetic activity feed and auto-build. V3: standalone WebGL2 woven torus, simulated agents, drift and repair. V4: source-backed code lens, 20 mapped symbols/15 cited source references from its own codebase, purpose/source/evidence tabs. All are **prototypes**; simulated engineering activity is not live harness telemetry.

## Acceptance for live Loom
1. One real run produces real agent events and visual motion.
2. One exact Git commit is inspectable by source identity.
3. One independent validation result links to a precise candidate and requirement.
4. Reconnect/replay reconstructs the same state deterministically.
5. Drift and completion cannot be asserted without evidence.
6. No UI action bypasses the harness authorization boundary.
