# C4 PostgreSQL race: bounded repair direction

**Verdict: CORRECT the C4 source; no completion claim.** The exact `078ed12c8b2cbaf102e8f788e37980b017fc061a` controlled local run applied migrations 001–006 to PostgreSQL 18.6, observed distinct backend connections, and passed ordinary bare-Git integration with one `slice.integrated` event and a released child. Its concurrent post-CAS replay failed with `A required final trusted certificate is missing or stale`. The run manifest reports `FAIL` and `STOPPED_OWNED_CLUSTER`; controlled receipt/review fixtures do not establish genuine trusted verification.

## Cause

`integrateVerifiedSlice` checks for an already integrated intent at governor line 142, then reads the awaiting slice and calls `trustedChecks.getCertificate` at line 152 before it can reach `finishIntegrationIntent`. On another SQL connection, the first caller may commit finalization between those reads. Finalization atomically changes the slice to `verified` and the intent to `integrated` (`sql-mission-store.ts:70-83`). `getCertificate` only returns a certificate while the slice is `awaiting_verification` (`sql-mission-store.ts:360`), so the second caller sees `null` and fails even though the same exact integration succeeded. The same race can surface at the awaiting-state check at governor line 144 or the second certificate read at line 157. This is an idempotent replay failure, not evidence that the first finalization lacked certificates.

## One narrow implementation direction

1. Keep all first-time, pending-intent admission checks at governor lines 143–159 and SQL `assertIntegrationCertificates` at lines 86–97. A missing certificate while the intent remains `pending`, an `unknown` intent, moved local ref, changed plan/policy, or conflicting request still fails closed. Do not make `getCertificate` serve verified slices merely to pass the race.
2. Add one bounded **completed-replay reconciliation** path at the few race-sensitive gates: initial read, awaiting-state mismatch, certificate miss, and finalization conflict. Re-read the durable intent and slice freshly. Proceed only if the intent is now `integrated` for the canonical exact request and the slice is `verified` for the same mission, slice, epoch, candidate, repository and approved plan. Require `observedIntegrationSha === candidateSha`, unchanged dedicated local ref, expected tree, review digest, required check set, certificate IDs/digests, plan digest and policy digest. Verify the retained review bytes and the persisted final PASS certificate/receipt bindings under the same SQL fence used by initial finalization. Return the already verified slice without another CAS, event insertion, or dependent release. A pending or conflicting read must preserve the original failure; never infer success from the ref alone.
3. Prefer reusing and strengthening the existing transactional `finishIntegrationIntent` idempotent branch (`sql-mission-store.ts:74-78`) as the single authoritative completed-replay fence, rather than duplicating SQL validation in the governor. Today that branch returns before `assertIntegrationCertificates`; include retained certificate identity/binding checks for completed replay and verify the persisted intent's review and observed SHA. The governor supplies fresh local-ref and review readbacks before calling it. Ensure the branch does not rewrite state or emit events.

## Deterministic proof required

- Force the second caller to pause after its initial `pending` read, allow the first caller to commit, then resume the second at each vulnerable gate. Use two independent SQL pools and controlled barriers, not scheduling luck. Both exact callers return the same verified slice; ref CAS advances once; one pending intent, one integrated event, and one child release remain.
- Repeat with absent/changed certificate or receipt while still pending, changed review/tree/plan/policy, `UNKNOWN` intent, and moved ref. Each must fail closed with no new integration event or child release.
- Run focused tests, freeze the source, run mandatory exact-candidate gates, and repeat the bounded real PostgreSQL/bare-Git proof. Preserve this failed run and report the successor run separately. Independent review must inspect the frozen repair before any C4 acceptance.

**Boundary:** The earlier C4 source PASS was a source-level assessment; this real PostgreSQL failure supersedes its concurrency assumption. It does not invalidate the observed ordinary integration in the retained run. Frozen broker/PR2 and provider/cloud state remain outside this repair.
