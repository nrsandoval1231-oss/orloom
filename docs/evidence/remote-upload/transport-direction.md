# C4-REMOTE-UPLOAD-01 transport direction (architecture only)

**Decision:** Implement a controller-owned Git HTTPS push from the fixed, already validated bare integration object store. This is an implementation/test slice; it confers no authority to publish to GitHub now. Bind the destination to the immutable parsed delivery policy and the configured repository identity, never to a command, candidate, or request URL. The only production URL is `https://github.com/<validated owner>/<validated repo>.git` and the only destination ref is the derived `refs/heads/orloom/delivery/<mission>/<slice-hash>`.

1. Reuse `BareGitFastForwardIntegrator.open`'s fixed bare path and identity, but expose a narrowly bounded uploader method or controller-owned path binding; do not infer a checkout path from the candidate. Before each attempted push, re-run the integrator's local store/ref/tree checks, revalidate the immutable policy and durable integrated/delivery intent, and require a fresh exact pinned remote base readback. Do not push protected refs or move the local integration ref. Use an explicit SHA-to-ref refspec without `+` or `--force`, `push --no-verify`, a fixed HTTPS URL, and bounded child-process timeout/output. An independently injected local bare remote transport is acceptable only in tests, never as a config-selected production destination.
2. Add an upload-specific App token minting method using the existing `POST /app/installations/{installation_id}/access_tokens` boundary with the one policy-derived repository name and `permissions:{contents:"write"}`. Do not reuse the existing `createInstallationToken` (`contents:read,checks:write`) or return the token through a route, event, persisted record, error, or log. Keep the token only in the Git child environment for its lifetime. A static installed askpass executable/script outside candidate and bare-repository paths returns fixed `x-access-token` for the username prompt and the token from a dedicated child env variable for the password prompt. Do not create a token file, put it in arguments or URL, or interpolate it into a command string. Verify the Windows and Unix helper invocation in an offline test; fail closed if the installed helper is missing or unsafe.
3. Spawn `git` via `execFile`/`spawn` with an argument array and explicit allowlisted environment. Disable system/global config, terminal prompts, inherited `GIT_*` tracing/config/exec-path, proxy and credential variables; set empty credential helper, disabled hooks, noninteractive askpass, and no replacement objects. Audit the bare repository's local config before upload: the existing `assertCompleteStore` does **not** reject `url.*.insteadOf`, `http.*.extraheader`, `credential.*`, or `core.askPass`. Reject transport-affecting or executable local config (including those keys, includes, filters, remote rewrites, protocol/SSH commands); do not assume the explicit URL alone defeats a rewrite. Discard child stdout/stderr from user-visible errors and logs; report a fixed reason code. Avoid `shell:true` and child inheritance of the controller's full environment.
4. Make upload a durable effect. Migration 007 constrains `mission_delivery_effects.effect` to `check|pull_request`, so add migration 008 for `upload` and extend `DeliveryEffectV1`. The existing SQL claim/observe transaction then serializes concurrent callers. Claim only after durable delivery intent and before first remote write. Distinguish **branch absent** from a failed/unauthorized REST readback; only a truly absent branch plus a *new* claim may push. After push, require a separate exact branch SHA/tree readback and pinned base readback before `observeDeliveryEffect(request,"upload",sha)`. On replay, an observed claim still requires fresh exact remote readback; a claimed-but-unobserved effect may be reconciled to exact observed SHA, but absent/moved/conflicting/ambiguous state stays `UNKNOWN` and is never blindly pushed again. No Check or PR claim may occur before observed upload and exact remote readback.
5. Test transport with local bare Git remotes and a fake App boundary; test the production factory rejects test URL injection. Cover duplicate concurrent calls, crash after remote ref write before acknowledgment, prior claim with absent branch, readback failure, wrong SHA/tree/base/repository/installation, missing helper/token, unsafe local Git config, protected ref, and no secret in errors/events/logs. No real provider request, credentialed push, or host mutation belongs to this source packet.

**Source basis:** base `884e91d5fb2760cc77bab9c75aae48d545dfc6e3`; `packages/integration/src/local.ts` currently has a private bare path and read-only/CAS Git operations; `packages/integration/src/delivery.ts` currently requires an already-present exact remote branch; `packages/adapters/src/providers.ts` App client is REST-only; `db/migrations/007_delivery.sql` has the effect constraint; `apps/control-plane/src/controller-authority.ts` already binds one trusted repository, App, installation, review reader, and policy. This direction is not source certification.
