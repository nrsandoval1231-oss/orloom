# Judgment, active recovery, and operational lessons

The composed source extends the historical C1 slice with durable, lease-fenced trusted-check progress and finite recovery decisions. A worker posts `orloom.progress.v1` to `POST /api/worker/missions/:missionId/slices/:sliceId/progress`; its mission, slice, epoch, plan digest, trusted check policy digest, recovery policy digest, and capability must match the active lease. `GET /api/worker/missions/:missionId/slices/:sliceId/recovery-policy` returns the operator-approved strategy map for that lease. Progress records contain fixed IDs, bounded counters, and SHA-256 evidence references, not prompts, stdout, source, or model reasoning.

The SQL store first persists an immutable snapshot and a `prepared` progress row. The snapshot binds the approved mission and slice budgets, mission-wide reserved cents, bounded worker-reported usage, and digest-only evidence references; reported counters are not metered provider cost. It releases its transaction before invoking the optional judgment adapter, then reopens a transaction and compares the active lease fence, snapshot revision, budget context, persisted progress/snapshot bytes under canonical JSON semantics, plan/check/recovery policy digests, and promoted-lesson binding. Only the Governor commits a finite action. A dispatched judgment with uncertain results, invalid output, an expired lease, or a changed fence becomes `UNKNOWN` and leaves the slice quarantined. `blocked` and `unknown` snapshots offer no continuation: deterministic handling escalates, while any injected nonterminal judgment is rejected and quarantined. Identical committed progress replays return the prior receipt only while the caller still proves the active lease; conflicting content and unresolved retries fail closed.

`createControlPlane` exposes explicit injection seams for judgment, scheduling and learning activation. Without an injected adapter, decisions use deterministic selection among the snapshot's approved strategy IDs. The Jev adapter uses the installed `@typesafe-ai/sdk` 0.6.0 `TypeSafeClient.systemOne` choice API, exact allowlisted model IDs, fixed HTTPS origin, bounded request/response bytes and deadline, and disabled retries. It cannot issue commands or change a plan. Production does not instantiate it by default. No credential, provider request, spend, or live Jev acceptance is claimed for this packet; an operator must provide exact model, credential, and a separately approved spend policy before configuring a live adapter.

An operational lesson is a versioned candidate based on two separate same-repository/scope-cohort episodes, each containing a trusted-check failure followed by a pass under a different approved strategy. Only observations with a committed Governor decision count: retained prepared or UNKNOWN progress remains queryable but is excluded from candidate provenance, regardless of whether it was recorded before or after a valid episode. The failure and pass in each episode must share the same target check, lease, and trusted/recovery policy digests; cross-target or cross-policy evidence cannot form a candidate.

Both stores derive the cohort by trimming and lowercasing each declared scope path, sorting the complete paths lexically, and taking the first path's first component. This makes scope ordering deterministic across memory and SQL stores. The cohort is only a coarse context label used to avoid combining some unrelated observations; it does not prove ownership or scope equivalence, and same-cohort candidates are not independently verified. SQL scans are bounded, and excluded observations remain persisted without entering candidate evidence. Candidates state the fixed metric (`trusted_check_pass_rate`), direction, comparable baseline/outcome counts, policy version/digest, rule, and four immutable progress event IDs. Candidates and their provenance are durable. The historical C1a checkpoint intentionally lacked independent challenge, promotion, downstream consumption and withdrawal; its 503 promotion response described that checkpoint, not the current composed source.

The current SQL-backed lifecycle includes independent trusted-evidence challenge, controller-owned activation gating, policy-governed promotion, subsequent bound strategy use and contradiction-driven withdrawal. Normal executable startup provides no learning-activation dependency, so source implementation is not live promotion: promotion fails closed through a Governor conflict (HTTP 409), rather than the historical unconditional C1a 503. An unavailable challenge dependency separately returns HTTP 503. The consolidation repairs require all supporting progress records and trusted attempts to be newer than the relevant retained negative/withdrawal cutoff, rechecking freshness at challenge persistence and promotion; stale candidates cannot block genuinely fresh replacements. Shared cohort normalization now also applies in Governor checks. Retained lessons and fixture ordering changes are not measured improvement, which remains null. See [repair validation](validation/2026-10-14-consolidation.md) and [foundation status](FOUNDATION_STATUS.md).

The controlled checks and Jev transport tests are fixtures. Their results do not establish product-build success, quality improvement, performance gain, provider capability, or live cost. The full recovery system remains open: this source does not yet complete near-identical patch fingerprints, provider/tool-call history and nonprogress attribution, regressing verification, blocked dependency recovery, or integration-conflict signals. Independent trusted-verification and Governor integration source now exist; their presence does not establish authentic exact-source runsc/cloud acceptance. The worker successor's hardened HTTP recovery transport passes controlled tests but is not connected to strategy/checkpoint execution. Candidate-bundle admission/import, cancellation propagation and durable interrupted-worker reconciliation remain separate open gates. PostgreSQL deployment/runtime claims require real-PostgreSQL proof bound to the relevant exact source; PGlite and older bounded proofs do not certify the successor.
