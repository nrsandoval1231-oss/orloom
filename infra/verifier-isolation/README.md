# Trusted local verifier

The default catalog entry remains `/usr/local/bin/node --check scripts/validate.mjs`, with cwd `/work/source` and its unchanged 60-second deadline. The optional `node-repo-suite-v1` entry uses an image-baked runner to admit the exact package/lock digest pair and run fixed TypeScript typecheck, clean build, nonempty Node test discovery/execution, and foundation validation stages. Image build installation includes development dependencies and uses the digest-pinned bundled npm with `--ignore-scripts` in a clean environment; verifier execution has no network. Its policy-bound deadline chain is 180 seconds for the whole image suite, 210 seconds plus the existing two-second kill-after for Docker attach, 225 seconds for the host launcher, and 240 seconds for the trusted attempt request. The existing 120-second reporting grace and request-contract maximum remain unchanged. These are conservative trial allocations, not proof that the complete suite fits; timeout or ambiguous cleanup remains UNKNOWN. Stage diagnostics are bounded advisory telemetry only. Both paths retain bounded result logs. The suite's offline path policy rejects workflow files, `.env` values other than `.env.example`, private-key formats, and `secrets/`, `credentials/`, and `state/` paths. It does not scan file contents for credentials or claim a vulnerability audit. Limits remain 1 CPU, 1 GiB, 128 PIDs, 512 MiB `/work`, 16 MiB `/tmp`, one verifier; host capacity still requires measurement.

The trusted host extracts raw blobs from an operator-mapped complete bare object store, verifies the candidate is reachable from the mapped ref and descends from the supplied base, then serializes a deterministic manifest and regular files. It rejects symlinks, gitlinks, traversal, case collisions, alternates, shallow stores, and partial/promisor stores. It stages under `/run/orloom-verifier-input` with a generated name, streams a tar archive over Docker stdin, and does not mount source or output paths into the container. The archive contains `manifest.json` and `source/`; it is extracted under `/work`, matching the reader's `/work/manifest.json`, source tree at `/work/source`, and policy cwd `/work/source`. The launcher requires a preloaded digest-pinned image, `runsc`, no network, read-only root, UID/GID 65532, dropped capabilities, no new privileges, fixed CPU/memory/PID limits, and bounded tmpfs. It obtains a non-blocking host-wide `flock` under `/run/orloom-verifier-lock` and records invocation plus exact container identity in `/var/lib/orloom/verifier/state`. The shared `/var/lib/orloom` parent must already be root-owned and non-group/world-writable; its permissions are checked but never changed. The dedicated verifier child is root-owned mode 0700. A prior known container is reconciled only by its recorded ID and matching ORL-C3/name/image labels; an intent without a known ID or a failed/mismatched inspection stays quarantined for operator reconciliation. No broad container enumeration or deletion is performed. The container rehashes every listed source file before running the fixed argv; bounded stdout/stderr and status return as one base64 JSON marker on Docker stdout. The marker must be unique, well-formed, untruncated, and agree with the launcher exit code; launcher stderr, infra exit, signal, timeout, disagreement, missing marker, truncation, or late finish are UNKNOWN. Cleanup releases the persistent intent only after the exact invocation container is successfully removed. Normal control-plane shutdown stops new polling and waits for any active verification before closing PostgreSQL.

`ORLOOM_VERIFIER_IMAGE` must be the immutable image reference, `ORLOOM_VERIFIER_ID` the configured trusted verifier identity, `ORLOOM_VERIFIER_ARTIFACT_ROOT` a persistent directory outside temporary folders and source worktrees, and `ORLOOM_VERIFIER_REPOSITORIES` a JSON object mapping canonical `owner/repo` to `{ "objectStore": "/absolute/path/to/repo.git", "approvedRef": "refs/heads/main" }`. The application factory disables the runner when any required value is absent. The host image must be built and its final image digest measured before configuring the factory; this repository does not assert that the derived image has been built or preloaded.

## Host proof proposal (not run)

The packet prohibits host changes from this builder. The following commands are for controller inspection and an explicitly selected bounded host-proof window. Run the read-only preflight first. It only inspects the already cached base image, Docker runsc registration, and available disk/memory. Node is inside the cached image; the derived image build verifies its binary hash without changing the protected container:

```sh
docker image inspect ghcr.io/openai/codex-universal@sha256:905e512f36460e1be4cfedb30928a8a28299edb0fcd5de7998ceaa72d27fe304
docker info --format '{{json .Runtimes}}'
df -h /var/lib/docker
free -m
```

After review, build from the pinned cached base and record the resulting local image ID without pushing it. Docker's local image ID (`sha256:<64 hex>`) is accepted as the immutable verifier image binding; no repository digest or registry is required:

```sh
docker build --pull=false -f infra/verifier-isolation/Dockerfile -t orloom-verifier:review .
docker image inspect --format '{{.Id}} {{json .RepoDigests}}' orloom-verifier:review
```

Before running a real candidate, the operator must provision the fixed `/run` staging root and persistent artifact root, configure one canonical bare object-store map/ref, and pass an actual extracted bundle to `LocalRunscLauncher`. Record image digest, input manifest digest, exact runsc runtime, wall time/resource observations, stdout/stderr hashes, and timeout/negative evidence. No source directory may be bind-mounted. A source-only smoke, this syntax check, and host preflight do not constitute the integrated private-route/PostgreSQL certificate proof.
