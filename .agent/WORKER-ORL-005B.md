# ORL-005B — Worker broker and candidate production

Status: dependent packet; do not dispatch until ORL-005A's exact candidate and `orloom.worker-lease.v1` HTTP routes pass independent review, and ORL-ISO-001 records a reviewed `runsc` launcher proof. Base SHA is the accepted ORL-005A head, to be recorded at dispatch; do not assume the present working tree is frozen.

## Objective and ownership

Make one approved mission slice travel through the actual lease API to an exact GitHub checkout, a bounded DeepSeek tool loop, a credential-free gVisor workspace, and a candidate/evidence handoff in `awaiting_verification`. The dedicated DigitalOcean worker is the broker; it is not a validator, integrator, GitHub publisher, or source of approvals. Implement on a focused branch after A is frozen. Builder owns `apps/worker/**`, `packages/agents/**`, worker-only Git/transfer/evidence helpers, affected worker tests, and worker operating docs. A's control-plane, contracts, Governor, Athena, migrations, Hostinger deployment, prototypes, and `work/worker-isolation/**` are excluded. Negotiate any missing A protocol field/transition with the controller as a separate interface repair; do not silently edit A's authority surface.

## Required interface and gates

Consume `packages/contracts/src/worker-protocol.ts` exactly: mission repository/base SHA, slice scope and checks, plan digest, capacity slot, lease epoch/tokens/expiry, trusted policy digest, and execution limits. Validate schema, identity, full SHA, expiry, provider allowlist, positive finite call/token/time/budget ceilings, and immutable plan/policy digests before checkout or provider use. A must expose fenced heartbeat, candidate, and typed blocked/unknown reporting with atomic durable events; if blocked/unknown reporting is absent, resolve that contract before dispatch. Never turn a worker response into verification or completion. A's owner-submitted plan remains a manual route; a real Sol-authored plan requires separately recorded model/provider and mission-bound provenance before that claim is made.

Live execution starts only after reviewed isolation evidence, measured host slot capacity, a securely supplied DeepSeek credential, explicit allowed model, approved spend limit, scoped GitHub read access, and durable evidence storage are all proven. A configured value or fake response is not proof. Missing prerequisite is `BLOCKED`; a timed-out provider call or interrupted operation whose effect is uncertain is `UNKNOWN`, with no blind retry. No model or GitHub calls may use the owner desktop OAuth cache. `/var/lib/orloom/codex` is broker-side Sol auth only and must never enter a candidate container.

## Broker flow

1. Claim only an approved READY slice through A, bind all subsequent calls to mission/slice/epoch/capability, and heartbeat while work is active. Respect the lesser of lease expiry and wall/time/cost limits; stop new tool/provider calls before crossing a limit.
2. Broker fetches only the named repository and exact base commit with a short-lived GitHub installation token limited to `contents:read` for that repository. The existing `providers.ts` token method requests `contents:read` plus `checks:write`; obtain a narrower token through a reviewed adapter change owned by the integration controller, never reuse the broader token for checkout. Use a private temporary checkout with sanitized Git environment (`GIT_CONFIG_NOSYSTEM`, blank global config, disabled hooks), no recursive submodules, LFS/smudge filters, external Git protocols, repository scripts, or inherited credential helpers. Verify the fetched commit matches `baseSha`; fail closed on mismatches. Do not run repository commands in the broker.
3. Transfer a bounded source snapshot into an ORL-ISO-001 fixed `runsc` container without host bind/volume mounts. Its image is digest-pinned; rootfs is read-only, process nonroot, network none, all capabilities dropped, no Docker socket, no provider/GitHub/Codex credentials, and bounded CPU, memory, PID, disk/scratch, and time. The trusted launcher accepts no arbitrary Docker flags. Use a fresh container and scratch area per lease, including concurrent leases.
4. Broker calls DeepSeek over HTTPS outside the container. `GET /models` must show the configured allowed model and required tool capability; each Chat Completions response must identify the expected model. Implement the actual function-call protocol with typed `read_file`, `list_files`, `apply_patch`, and `run_check` operations. Parse and validate all model arguments; paths must stay inside allowed slice scopes after normalization, `lstat`/realpath and symlink checks. Reject absolute/traversal paths, `.git`, hooks/config files, symlink escapes, oversized edits/logs, and calls outside the allowlist. Only fixed tool implementations execute inside the sandbox. There is no model tool for host shell, Docker control, network, or credentials. `run_check` resolves IDs from the trusted policy digest, never raw plan text or a model-supplied shell command. Offline dependencies must be pre-staged/pinned; do not relax network isolation for package installation. Treat sandbox stdout/stderr as untrusted bytes: bound, redact, and classify before exposing any excerpt to model context, mission events, logs, or evidence.
5. Cap provider calls, input/output tokens, wall time and reported usage/cost against the lease reservation. Treat malformed tool calls, unexpected model IDs, provider 4xx/5xx, partial streams, missing usage, and timeout distinctly; preserve redacted evidence and stop safely. Never substitute Codex/OpenAI for DeepSeek.
6. Retrieve only bounded changed files/diffs from the sandbox through the fixed transfer path. Recheck paths, symlinks, file types, scopes, size, base identity, and no protected files before applying to a credential-free staging checkout. Create a local candidate commit and verify its full SHA/tree. Integrate the existing content-hash/conditional-write R2 adapter in `providers.ts` through its interface; do not create a second artifact protocol. Write immutable digest-addressed diff, command, provider-usage, and policy evidence to the configured durable store and verify readback/digests. Evidence/event payloads contain structured statuses and sanitized bounded excerpts only, never raw untrusted stdout or secret-bearing environment. Send the candidate SHA and evidence references to A under the live fenced lease. A records `awaiting_verification`; independent clean-workspace checks and review remain later gates. No push, PR, check-run publication, merge, or deployment in this packet.

## Acceptance and handoff

Deterministic integration test traverses real A HTTP routes and an isolated disposable Git repository: claim, exact checkout, broker-to-sandbox tool operations, fenced heartbeats, scope rejection, candidate commit, durable evidence, and `awaiting_verification`. Use injected provider/transport for tests, but run real `runsc` isolation tests separately against ORL-ISO-001. Test concurrent distinct leases, stale epoch/token rejection, expired lease, provider uncertainty, budget exhaustion, malformed tool calls, hostile Git attributes/hooks/submodules, path traversal, symlink escape, and no credential leakage. Run focused worker checks, then `npm ci`, typecheck, tests, build, validate, and diff check on the frozen candidate. A real disposable-repository DeepSeek run is required for live acceptance once credentials and capped spend are authorized; fake-client tests alone are implementation evidence. Record exact SHA, commands/exits, model ID returned by `/models` and responses, usage/cost measured versus UNKNOWN, artifact digests, sandbox proof reference, and remaining gates in `COMPLETION.json`. Two materially different repair attempts maximum; no self-certification.
