# C1b architecture decision and bounded build packet

Decision: build one evidence-bound recovery lesson loop. A trusted check attempt during an active recovery lease supplies the independently executed FAIL or PASS outcome; worker progress names that attempt but cannot define its result. A separate challenger reopens the persisted receipt and artifacts, recomputes two comparable failed-to-passed episodes, and records an immutable challenge. The Governor alone promotes a scoped lesson, includes it in a later comparable decision, and withdraws it when a trusted contradictory result arrives. This is an active behavior change, not a lesson listing or a claim of improved live performance.

**Challenge and promotion.** Candidate generation may remain a provisional hint, but the challenger resolves the candidate's four committed event IDs to two separate comparable episode pairs, then to four distinct trusted attempts. It independently rereads receipt/artifact bytes through the trusted artifact reader, validates digests and requests against approved policy and exact commits, checks different episodes, ordered fail→Governor-approved strategy→pass transitions, and recomputes the existing 2/2 paired `trusted_check_pass_rate` observation. This metric describes the observed paired conversion only; it is not a causal speed or quality estimate. A challenge result records verifier identity, algorithm/policy version, all event/attempt/candidate/receipt/artifact digests, comparison scope, metric, decision and reason. An invalid challenge is durably rejected. The challenger must run under a controller identity distinct from the worker and the trusted-runner submission capability; a free-form `reviewer` string or worker-supplied challenge is not authority.

   Promotion is a Governor transaction under the existing global mission lock. Recheck the immutable accepted challenge, current strategy allowlist, recovery and trusted-check policy digests, repository/cohort/target, no conflicting active lesson, and candidate version. Append an `operational_lesson_events` promotion with the exact challenge digest and activate only that version. Idempotent replay returns the same promotion; concurrent conflicting promotions fail. No promotion may arise from a C3 PASS certificate alone.

**Later task and contradiction.** On a later comparable mission/slice (different episode), query only the latest promoted, unwithdrawn version matching repository, cohort, target check, policy and an approved untried strategy. Extend `DecisionSnapshotV1.lessonBindings` in `packages/judgment/src/types.ts` with **required `challengeDigest`** alongside exact lesson ID, `lessonVersion`, recovery `policyDigest`, and strategy ID; the recovery policy digest is not the lesson challenge digest. The Governor checks the selected strategy against the same fresh snapshot and current promoted ID/version/challenge digest immediately before committing its action. The action/event persists that binding and chosen strategy; actual next progress must use the authorized strategy. A withdrawn or changed lesson between preparation and commit invalidates the judgment and quarantines or safely re-evaluates it under a fresh snapshot; it is never silently applied.

   If a subsequent comparable attempt **under the promoted strategy**, as bound at attempt creation, yields a trusted terminal FAIL for the same target/check/policy, append contradiction evidence and atomically withdraw that version under the same lock. Keep its history and prior decisions; new snapshots omit it. UNKNOWN and worker reports do not withdraw. A later replacement, if supported, must get a greater version and a new independent challenge. One trusted contradiction triggers conservative withdrawal; this is a safety rule, not a statistical estimate of harm.
