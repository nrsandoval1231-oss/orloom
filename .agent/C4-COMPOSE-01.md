# Controller composition direction — C4-COMPOSE-01

**Decision: one conditional startup-composition slice after delivery acceptance.** The present `apps/control-plane/src/main.ts` calls `createControlPlane(config,jobs,missions,undefined,trustedChecks)` and injects no local integration authority, delivery controller, recovery judgment adapter, or scheduling adapter. The server already has those dependency-injection slots and owner-session routes. Do not build another orchestration framework or change the routes. The observed `work/orloom-delivery` checkout is currently dirty with an unresolved `packages/governor/src/governor.ts` merge; it is not the packet base. Root must finish serial integration, accept C4 delivery, and provide a clean exact base SHA before dispatch.

## Architecture boundary

Use one small startup factory called by `main.ts` in cloud/SQL mode. It may construct only existing production components: `BareGitFastForwardIntegrator.open`, a bounded retained-review reader, `createR2ArtifactStore`, `createGitHubAppAdapter`, `JevClient`, `createJevRecoveryAdapter`, and `createJevSchedulingAdapter`. Pass resulting authorities/adapters into the existing `createControlPlane` arguments. No request-supplied repository, installation, base, ref, check policy, provider, model, or spending settings. Missing or partial configuration leaves that capability unavailable; an explicitly enabled but invalid configuration fails startup with field names only. Never log or return secret values. Keep the existing default closed behavior.

The integration authority needs a configured canonical repository identity and an operator-owned bare Git path, plus retained independent review bytes. The reviewer reader must accept only bounded artifact IDs, read one regular file beneath a configured private root without symlink escape, cap bytes, and return `null` on absence; Governor already verifies exact digest, PASS, candidate/tree, reviewer/builder separation, and scope. The bare repository must be fixed at startup, never chosen by the request. No worker checkout, PR #2 ref, or production repository should be inferred from a mission field.

The delivery controller needs an immutable single-repository policy (repository, App and installation IDs, pinned base ref/SHA, protected refs, full-suite check set, policy version/digest, image digest, Check name), the same local integrator and reviewer reader, R2 artifact store, and GitHub App adapter. Read policy from a private operator-owned JSON file or equivalent strict config; validate exact shape and repository equality with the local integrator before injection. Read secrets via the existing `_FILE` pattern, preferring file-backed App private key and R2 keys; pass them only to adapters and never serialize them into `Config`, logs, events, or browser responses. Startup composition grants no remote-write permission by itself: only the existing authenticated delivery command may publish after its durable fences. Current delivery code consumes an **already uploaded** reserved branch after exact remote SHA/tree and base readback. Remote Git upload, actual App installation and R2 credentials, and credentialed disposable-repository proof are separate later nodes. Do not claim end-to-end delivery from this startup slice.

Jev composition is separate and optional within the same small factory. Enable it only with an explicit operator flag, a file-backed API key, an exact allowlisted model ID, bounded input/response/timeout limits, and a stated spend/budget policy consistent with the existing client. Reuse the current finite recovery/scheduling adapters and Governor revalidation. No provider call at startup or in tests. If the policy or credential is absent, inject neither adapter; if enabled configuration is malformed, fail startup closed. Do not introduce model fallback, retries, or a new decision path.

Trusted verification remains its existing startup component. Do not widen `getCertificate`, weaken the mandatory `node-repo-suite-v1` full-suite check, or turn a syntax-only verifier into delivery authority. If the configured verifier does not issue the required exact full-suite certificate, integration/delivery remain closed.
