## Required seam

B emits an awaited, bounded progress record before and after each provider request, model tool action, trusted check, and candidate handoff. Each record binds mission ID, slice ID, lease epoch, monotonically increasing attempt/action ordinal, stable event ID, phase, outcome, tool/check ID, normalized scope digest, patch/diff digest, bounded token/call/time counters, and immutable evidence refs. Never send raw prompts, reasoning, source, stdout, secrets, or untrusted error text as event data. A fenced worker endpoint authenticates both lease and capability, deduplicates event ID, rejects stale/out-of-order records, and transactionally appends the event plus the recovery decision. The broker awaits that decision and checks the fence before any next effect. Loss of acknowledgement or an ambiguous provider/tool effect becomes UNKNOWN; it is not replayed to fill an event gap. R2 attempt blobs and a terminal result alone do not satisfy this seam.

## Bounded policy and state transitions

Derive signals from durable records, not a model's self-report: repeated normalized error fingerprints, repeated identical patch/tree digests, no diff or check progress across bounded actions/time, blocked dependencies, and a check regression. A single failed check is not automatically stuck. Persist signal, attribution, policy version, evidence refs, selected action, and outcome under the lease epoch. Default maximum is two *materially different* in-lease corrective strategies per slice; each has a distinct strategy ID and explicit expected signal/check change. B must apply an approved `change_strategy` directive to its next prompt/tool choice inside the same scopes, lease, budget, model allowlist, and deadline; no new privilege or silent retry. On success, continue. On repeated failure, emit BLOCKED with a durable Sol replan request and hold A's existing quarantine. On uncertain interrupted effects, emit UNKNOWN and require reconciliation before any reissue. Never release slot, scope, or budget merely because a model says it recovered.

The Sol planner/replanner is one mission-bound interface in the existing orchestrator path: it consumes the canonical mission, approved plan, exact base/integrated head, progress/evidence, and constraints; it proposes a versioned replacement graph and rationale. The current owner-authored recommendation is not Sol planning. C records a `replan_requested` artifact and validates any returned proposal against A's graph/budget/scope policy, but it cannot auto-replace an approved plan, unblock dependencies, or advance the execution base. A later explicitly reviewed plan-revision and approval transition must authorize those actions. Do not add a second scheduler or treat a proposed plan as executable.

## Learning path

From the same durable episodes, create candidate lessons with a precise rule, task/repository scope, attribution, positive or negative evidence, named metric and desired direction, baseline/comparator definition, policy version, and withdrawal trigger. A deterministic validator rejects missing evidence, incomparable cohorts, post-hoc metrics, regressions, and any rule that weakens scope, checks, cost, approval, or verification. Promote only after repeatable comparable results and, for code-quality/completion claims, independent exact-head verification from D. Until D exists those claims remain candidates. Version and retain promotion/withdrawal events; never overwrite history. The broker consumes only currently promoted, relevant policy lessons through a bounded snapshot whose digest is recorded before the next slice/strategy decision. Demonstrate an operational lesson changing a subsequent authorized strategy in deterministic tests, without claiming live time, cost, or quality gains from fixtures.
